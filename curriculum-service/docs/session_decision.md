# 대화 세션 관리 의사결정

## 배경

API Gateway는 사용자 인증 후 `X-User-Id`와 `X-Role` 헤더를 curriculum-service에 전달합니다. 서비스는 사용자별로 하나의 강좌 추천 대화를 유지하되 대화 내용을 영속화할 필요는 없습니다.

## 결정

- 검증된 `X-User-Id`를 LangGraph의 `thread_id`로 사용합니다.
- 사용자당 하나의 인메모리 대화 세션만 유지합니다.
- 마지막 요청 처리가 끝난 후 30분 동안 활동이 없으면 세션을 만료시킵니다.
- 만료는 요청 진입 시 확인하고 백그라운드 작업으로도 주기적으로 정리합니다.
- 만료 후 첫 메시지는 새 대화의 첫 메시지로 처리합니다.
- `DELETE /chat/session`으로 사용자가 현재 세션을 직접 삭제할 수 있게 합니다.
- 동일 사용자의 동시 요청은 순서대로 처리합니다.
- 백오피스 API는 유효한 `X-User-Id`와 정확히 일치하는 `X-Role: ROLE_ADMIN`을 요구합니다.
- `/health`는 인증 대상에서 제외합니다.

## 결정 사유

- Gateway가 검증한 사용자 ID를 사용하면 클라이언트가 대화 식별자를 임의로 선택하거나 다른 사용자의 세션에 접근하는 것을 방지할 수 있습니다.
- 대화를 영속화할 필요가 없으므로 인메모리 저장 방식을 사용해 구현과 운영 복잡도를 낮춥니다.
- 요청 시 만료 검사와 주기 정리를 함께 사용해 만료된 대화의 재사용을 막고, 다시 요청하지 않는 사용자의 세션도 메모리에서 제거합니다.
- 사용자별 요청을 순차 처리해 동일한 체크포인트에 대한 동시 쓰기로 대화 상태가 뒤섞이는 것을 방지합니다.
- 명시적 삭제 API를 제공해 사용자가 만료를 기다리지 않고 새로운 추천 대화를 시작할 수 있게 합니다.
- 백오피스 권한을 서비스에서도 검사해 일반 사용자의 관리 기능 접근을 차단합니다.

## 운영 및 보안 전제

- 서비스는 단일 인스턴스로 운영하며 재시작 시 세션 소실을 허용합니다.
- 외부 클라이언트는 서비스에 직접 접근할 수 없고 API Gateway만 접근합니다.
- Gateway는 클라이언트가 보낸 `X-User-Id`와 `X-Role`을 제거하거나 인증 결과로 덮어씁니다.
- 다중 인스턴스 운영이 필요해지면 고정 라우팅 또는 공유 체크포인터를 별도로 도입합니다.
