# Gateway 인증 기반 대화 세션 작업 계획

## 목표

Gateway가 전달하는 사용자 정보를 신뢰하여 사용자당 하나의 인메모리 대화 세션을 제공하고, 30분 비활성 만료, 명시적 초기화, 백오피스 권한 검사를 구현합니다.

## 작업 1. Gateway 헤더 인증 및 관리자 권한 검사

- 공통 FastAPI 의존성을 추가합니다.
  - `X-User-Id`: 공백 제거 후 1 이상의 정수인지 검사
  - 누락 또는 잘못된 값: `401 Unauthorized`
  - `X-Role`: `ROLE_ADMIN`과 대소문자를 구분하여 정확히 비교
  - 관리자 역할 누락 또는 불일치: `403 Forbidden`
- 모든 `/api/courses` 백오피스 엔드포인트에 사용자 인증과 관리자 권한 검사를 적용합니다.
- `/health`는 인증 없이 유지합니다.
- 허용·거절 시나리오와 거절 시 `CourseService`가 호출되지 않는 경우를 테스트합니다.
- 관련 테스트 통과 후 커밋합니다.
  - `feat(curriculum): Gateway 헤더 인증과 관리자 권한 검사 추가`

## 작업 2. 인메모리 세션 수명 주기 구현

- LangGraph의 `InMemorySaver`와 컴파일된 그래프를 사용하는 세션 서비스를 추가합니다.
- 정규화한 `X-User-Id`를 내부 `thread_id`로 사용합니다.
- 사용자별 마지막 활동 시각과 실행 상태를 단조 시계 기준으로 관리합니다.
- 동일 사용자의 채팅·삭제 요청은 비동기 잠금으로 직렬화하고, 다른 사용자의 요청은 병렬 처리합니다.
- 마지막 채팅 처리가 끝난 후 30분 이상 지나면 해당 사용자의 모든 LangGraph 체크포인트와 세션 메타데이터를 제거합니다.
- 채팅 처리 중인 세션은 만료시키지 않습니다.
- 요청 진입 시 만료를 검사하며, 60초 주기의 백그라운드 작업으로 재접속하지 않는 세션도 제거합니다.
- 다음 환경 변수를 `app/config.py`에 추가하고 양의 정수만 허용합니다.
  - `SESSION_TIMEOUT_SECONDS=1800`
  - `SESSION_CLEANUP_INTERVAL_SECONDS=60`
- 가짜 시계를 사용하여 유지, 경계 시각 만료, 주기 정리, 사용자 격리, 동시 요청 직렬화, 처리 중 만료 방지를 테스트합니다.
- 관련 테스트 통과 후 커밋합니다.
  - `feat(curriculum): 인메모리 대화 세션 수명 주기 추가`

## 작업 3. 채팅 및 세션 초기화 API 적용

- `POST /chat`에 `X-User-Id` 인증을 적용합니다.
- 요청 본문에서 `thread_id`를 제거하고 `message`만 받습니다.
  - 기존 클라이언트가 `thread_id`를 보내더라도 추가 필드로 무시합니다.
  - 본문 값은 사용자 식별에 사용하지 않습니다.
- 응답에서 `thread_id`를 제거합니다.
- 만료 후 첫 요청은 오류를 반환하지 않고 새 대화의 첫 메시지로 처리합니다.
- `DELETE /chat/session`을 추가합니다.
  - `X-User-Id`로 현재 사용자의 세션을 식별합니다.
  - 세션 존재 여부와 관계없이 멱등하게 `204 No Content`를 반환합니다.
- `InMemorySaver`를 애플리케이션 구성 단계에서 생성하여 그래프와 세션 서비스에 함께 주입합니다.
- lifespan에서 세션 정리 작업을 시작하고 종료 시 안전하게 중단합니다.
- 인증 오류, API 스키마, 사용자별 상태 유지, 명시적 초기화, 만료 후 새 대화를 테스트합니다.
- lifespan과 기존 워크플로우 회귀 테스트를 실행한 후 커밋합니다.
  - `feat(curriculum): 사용자 기반 채팅 세션 API 적용`

## 완료 조건과 커밋 원칙

- 잘못된 `X-User-Id`는 그래프나 `CourseService`를 호출하지 않고 `401`을 반환합니다.
- 백오피스는 유효한 사용자이면서 `ROLE_ADMIN`인 경우에만 접근할 수 있습니다.
- 동일 사용자는 하나의 대화만 유지하고 사용자 간 상태가 섞이지 않습니다.
- 30분 비활성 세션은 요청 시 또는 백그라운드 정리 시 제거됩니다.
- 명시적 초기화 이후 다음 메시지는 새 대화로 처리됩니다.
- 신규 외부 라이브러리와 영속 저장소는 추가하지 않습니다.
- 각 작업은 관련 테스트가 통과한 뒤 명시된 메시지로 독립 커밋합니다.
- 테스트 실행은 프로젝트 규칙에 따라 사전 승인을 받은 뒤 수행합니다.
- 스테이징은 파일 경로를 명시하여 수행하고, 사용자 소유의 `PLAN.md`와 관련 없는 파일은 커밋하지 않습니다.
- 커밋 후 경미한 수정이 필요하면 `git commit --amend --date=now`를 사용합니다.

## 운영 전제

- curriculum-service는 단일 인스턴스로 운영하며 재시작 시 대화 소실을 허용합니다.
- 외부 클라이언트는 서비스에 직접 접근할 수 없고 Gateway만 접근합니다.
- Gateway는 클라이언트가 보낸 `X-User-Id`와 `X-Role`을 모두 제거하거나 인증 결과로 덮어씁니다.
- 다중 인스턴스로 전환할 경우 UserId 기반 고정 라우팅 또는 Redis 계열 공유 체크포인터를 별도로 설계합니다.
- 초기 구현에서는 대화 턴 수 제한을 두지 않습니다. 장시간 활성 대화의 메모리 사용량은 향후 운영 지표에 따라 제한합니다.
